# Comprehensive README & Project Documentation Standards

When creating or updating `README.md` and documentation for ANY project, always adhere to the following exhaustive standards:

1. **Full Information & Zero Placeholders**:
   - Every README must provide complete, production-grade architectural and operational documentation.
   - Never write minimal or stub README files.

2. **Visual Hierarchy & Assets**:
   - Modern badges (build status, languages, cloud providers, licenses, tools).
   - High-impact banners and vector diagrams (SVGs in `assets/` or embedded visualizations).

3. **Mermaid Diagrams**:
   - **System Architecture**: High-level component interactions, subgraphs, data flows.
   - **Algorithmic Decision Flows**: Detailed conditional branches, validation stages, fallback logic.
   - **Sequence Diagrams**: Chronological event messaging, API calls, error handling loops.
   - **Mindmaps / Framework Alignments**: Well-Architected Framework, security boundaries, operational pillars.

4. **Structured Tables**:
   - Value matrices (Traditional Manual vs Automated Solution).
   - Configuration & Environment Variables reference table (Names, Types, Default Values, Descriptions).
   - IAM Permissions / Security Matrix (Action, Resource ARN, Justification).
   - Troubleshooting & Error Resolution Matrix (Error Code / Symptom, Cause, Immediate Remediation).

5. **Full Directory Topology**:
   - Exhaustive ASCII/Unicode directory tree with annotated descriptions for every file and folder.

6. **Interactive Run & Web Blueprints**:
   - Clear, step-by-step launch instructions (CLI, local runner, Web Console, browser one-click, IaC / Terraform).
